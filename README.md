# 订单交付风险分析助手

面向制造业计划主管的订单风险协作产品原型，将订单、包装计划与工单预警组织为可核实、可追问、可跟进的风险事项，帮助用户从发现异常走向证据核对和责任协同。

## 业务背景

判断订单是否需要提前干预，需要结合订单数量、客户交期、公司评审交期、包装安排与工单预警。查到数据之后，计划人员仍需整理判断依据、核实原因，并明确后续由谁处理。

项目围绕四个问题设计核心体验：**优先关注哪张订单、判断依据是什么、还缺哪些信息、下一步由谁核实**。通过风险事项连接分析结果与人工处理，保留业务人员对原因和建议的判断。

## 我的工作

- **需求与范围定义**：梳理订单交付风险场景，形成产品方案和多轮 PRD，明确目标用户、首版主流程及人工确认点。
- **数据与规则设计**：整理订单数量、交期、包装计划与预警的关联口径，区分可计算事实、原因候选和待补信息，并根据数据条件调整需求范围。
- **交互原型与迭代**：借助 AI 辅助编码完成会话、风险看板和详情页面，完善连续追问、建议修改、责任人指派及异常反馈。

## 核心体验

### 从自然语言问题进入风险分析

用户可以按合同、产品、客户或时间范围发起查询。回答围绕当前风险组织结论、事实、原因候选、证据缺口与处理建议，并支持继续追问规则依据，保持任务上下文一致。

### 在看板中确定优先核实事项

看板聚合风险订单、临近交期、包装缺口和数据不足等信息，并按合同组织风险事项。用户可按建议等级筛选，区分风险判断、建议等级与处理状态，确定需要进一步核实的对象。

![订单交付风险看板与待处理事项](docs/screenshots/workbench.png)

### 核对证据，形成人工处理决定

详情页集中展示订单事实、包装计划、工单预警、规则依据和待补信息。用户可以修改、采纳或驳回建议，再指派责任人并更新处理状态；原建议和人工操作保留记录。

![风险证据核对与人工决策](docs/screenshots/detail.png)

## 关键设计取舍

| 业务问题 | 设计方式 |
|---|---|
| 风险分析中的数量和日期需要可复核 | 规则层计算事实与风险，问答层围绕结果组织解释，避免由回答临时生成指标 |
| 数据缺失时无法支持完整判断 | 保留“数据不足”状态，区分已确认事实、原因候选、反证与待补信息 |
| 一段分析文字难以持续跟进 | 将同一合同的相关问题聚合为风险事项，连接建议、责任人和处理状态 |
| 建议需要业务人员核实和修正 | 支持修改、采纳、驳回与指派，并保留原建议及操作记录 |
| 连续追问与角色切换可能造成上下文或权限混淆 | 限定当前合同的追问范围，由状态机校验操作权限，问答异常时仍可查看事实 |

## 当前成果

已形成“发起分析—筛选风险—核对证据—确认建议—指派跟进”的交互原型，将业务规则、证据展示与人工协作串联起来。

当前使用模拟快照和本地模板问答，页面操作仅更新浏览器中的演示状态，未接入真实模型及 ERP / MES。后续接入以真实数据关联和证据完整性验证为前提。

## 技术与运行

原型采用 HTML、CSS 和 JavaScript，按样例数据、业务规则、状态管理、问答和页面展示分层组织。
