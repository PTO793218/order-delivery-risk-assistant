# 订单交付风险分析助手

面向制造业计划主管的订单风险协作原型，将分散的订单、包装计划与工单预警组织成可核实、可指派、可追问的风险事项。

本项目展示我如何从业务场景出发，梳理数据口径、定义 AI 与规则的分工，并将需求落实为可交互原型。当前公开版本使用模拟快照和模板问答，主要对应 V0.3；后续 PRD 已迭代至 V0.4。

![订单风险工作台](docs/screenshots/workbench.png)

## 业务问题与产品目标

订单是否需要提前干预，需要结合客户交期、公司评审交期、剩余数量、包装安排和工单预警判断。这些信息分散在不同业务记录中，计划人员查到数据后，还需要整理依据、核实原因并协调责任人。准时交付率反映履约结果，日常工作还需要更早识别待核实事项。

我将首个目标用户聚焦为计划主管，把成功体验定义为能够回答四个问题：**优先关注哪张订单、依据是什么、还缺什么信息、下一步由谁核实**。产品以“风险事项”承接分析结果，将查看信息与后续人工处理连起来。

## 我的工作与交付

- **需求与范围**：梳理订单交付风险场景，形成产品方案和多轮 PRD，明确核心用户、首版流程与人工确认点。
- **数据与规则**：整理订单数量、交期、包装计划和预警的关联口径，区分可计算事实、缺失字段和待确认原因。
- **原型与验证**：借助 AI 辅助编码实现会话、看板、详情及人工决策流程，通过场景检查迭代页面、文案、权限与异常处理。

主要交付为产品方案、PRD、可运行原型和验证材料。当前仓库提供脱敏展示代码、[产品设计说明](docs/product-design.md)与[验证记录](docs/verification.md)。

## 关键产品决策

| 决策 | 判断依据 | 在原型中的体现 |
|---|---|---|
| 将确定性计算与 AI 解释分开 | 数量、日期和风险规则需要可复核；AI 的价值在于组织证据、解释结果和支持追问 | 规则层计算风险，问答层围绕结果说明事实、证据缺口与建议 |
| 以风险事项组织协作 | 一段分析文字还需要转化为可跟进的处理对象 | 合同风险聚合进入看板，保留建议、人工修改、责任人和操作记录 |
| 把证据缺口与人工确认放进主流程 | 关联信息不足时，原因和建议需要业务人员核实 | 展示待补信息与原因候选；用户可修改、采纳、驳回和指派 |

**AI 体验的设计目标** 是减轻用户在多张记录之间整理信息、解释风险和准备处理建议的工作。当前模板问答用于验证输入、回答结构、连续追问和人工确认流程；真实模型接入后的效果仍需要单独评测。

## 一个完整的用户任务

用户输入“分析合同25DMO00001W-AA、产品5756为什么有交付风险？”后：

1. **核对事实**：模拟订单数量为 200 件，已交 0 件，预定 166 件，按既定口径得到待包装缺口 34 件；客户交期与公司评审交期分别展示。
2. **解释依据**：回答区分风险结论、事实与证据、原因候选、缺失或冲突证据、处理建议和人工确认事项。用户可继续追问命中了哪些规则。
3. **进入处理**：打开风险详情，查看包装计划、工单预警和证据；修改建议后采纳，再指派责任人，保留原建议与人工操作记录。

这一任务用来验证用户能否从分析走到核实与处理。示例日期固定在历史快照中，页面操作仅保存在浏览器内存。

## 迭代与验证

**数据条件推动范围调整**。早期方案覆盖较完整的风险研判；后续数据调研发现，包装计划关联、公司评审交期和理论生产周期等条件仍需确认。V0.4 PRD 因此将首版重点收缩为“订单事实查询 → 证据与缺口整理 → 人工确认和指派”，把依赖完整数据的风险判断后移。此调整属于需求规划，公开原型仍主要对应 V0.3。

**交互验证推动页面精简**。在保留合同、数量、交期、规则编号、证据来源和人工确认要求的前提下，减少重复引导与长篇说明，让用户更容易找到需要核实的内容。

验收重点包括：缺字段时保持“数据不足”；跨合同追问隔离；AI 降级后仍可查看事实；人工修改保留原建议；角色权限由状态机校验。作品集发布时，52 项规则、状态与静态检查以及 Chrome 主流程检查通过，详见[验证记录](docs/verification.md)。

**阶段成果**：已形成需求、业务口径、原型和验证材料相互对应的产品交付。尚未接入真实模型与 ERP / MES，也未取得上线后的效率、采纳率或交付改善数据。后续应先验证真实数据可用性，再评测回答依据完整度、人工修正情况与任务完成体验。

## 体验原型

在仓库根目录执行 `python -m http.server 4173 --bind 127.0.0.1`，打开 <http://127.0.0.1:4173/>。Windows 可双击 `启动原型.bat`。

```bash
npm ci
npm test
npm run test:browser
```

浏览器检查默认使用 Windows Chrome，可通过 `CHROME_PATH` 指定路径。固定快照基准日为 `2025-02-12`。所有人工操作仅更新演示状态，刷新或重置后恢复，不执行业务写回或外发。
